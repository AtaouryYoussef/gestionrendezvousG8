APERÇU DU PROJET
================================================================================

Nom du projet : SmartQueue
Version : 1.0.0
Type : Application mobile React Native (Expo)
Objectif : Système de réservation et de gestion de rendez-vous

Description :
SmartQueue est une application mobile conçue pour aider les utilisateurs à gérer 
leurs rendez-vous facilement. L'application fournit une interface rationalisée 
pour planifier des rendez-vous avec divers services et suivre le statut des 
rendez-vous.

ARCHITECTURE DE BASE DE DONNÉES
================================================================================

Type de stockage : Base de données NoSQL en mémoire (Développement)
Implémentation : Magasin d'objets JavaScript en mémoire

Collections :
1. users       - Comptes utilisateurs
2. appointments - Réservations de rendez-vous
3. services    - Services disponibles

Opérations prises en charge :
- getCollection(collectionName) - Récupérer tous les documents
- insertDocument(collection, doc) - Ajouter un nouveau document
- updateDocument(collection, id, update) - Mettre à jour/upsert un document
- deleteDocument(collection, id) - Supprimer un document

Couche de persistance :
- AsyncStorage pour la session utilisateur connecté
- Magasin en mémoire pour les données d'application (réinitialise au rechargement)

Note : L'implémentation actuelle utilise le stockage en mémoire. Le déploiement 
en production nécessiterait la connexion à une base de données NoSQL persistante 
(MongoDB, Firebase, etc.) en implémentant la fonction connectToNoSQL().

VALIDATION ET SÉCURITÉ
================================================================================

Validation d'email :
- Modèle Regex : /^\S+@\S+\.\S+$/
- Assure un format d'email valide
- Pas d'espaces autorisés

Validation de mot de passe :
- Longueur minimale : 6 caractères
- Appliquée à l'inscription et à la connexion

Validation de nom :
- Longueur minimale : 2 caractères
- Vérification de champ obligatoire

Considérations de sécurité :
- Mots de passe stockés en texte brut (DÉVELOPPEMENT UNIQUEMENT)
- La production nécessite : hachage de mot de passe (bcrypt/argon2)
- Pas de jetons d'authentification implémentés
- Session stockée dans AsyncStorage (non cryptée)

NOTES DE SÉCURITÉ IMPORTANTES :
⚠️ L'implémentation actuelle est à des fins de développement/démonstration uniquement
⚠️ Le déploiement en production nécessite :
   - Hachage et salage des mots de passe
   - Authentification JWT ou OAuth
   - Chiffrement HTTPS/SSL
   - Gestion sécurisée des sessions
   - Assainissement des entrées
   - Limitation de débit
   - Protection CSRF

FLUX DE DONNÉES
================================================================================

Flux d'authentification :
1. L'utilisateur entre les identifiants sur LoginScreen
2. Appelle login() depuis AuthContext
3. AuthContext appelle localDatabase.loginUser()
4. La base de données recherche dans la collection users
5. Si trouvé, l'utilisateur est stocké dans l'état du contexte
6. L'utilisateur est sérialisé dans AsyncStorage
7. AppNavigator détecte le changement d'état utilisateur
8. Bascule vers la navigation authentifiée

Flux de création de rendez-vous :
1. L'utilisateur navigue vers BookAppointmentScreen
2. Récupère les services depuis localDatabase
3. L'utilisateur sélectionne service, date, heure
4. Appelle localDatabase.addAppointment()
5. Le nouveau rendez-vous est ajouté au magasin en mémoire
6. La navigation retourne à l'écran précédent
7. AppointmentsScreen récupère les rendez-vous de l'utilisateur
8. La liste mise à jour est affichée à l'utilisateur

Flux de mise à jour du profil :
1. L'utilisateur clique sur "Modifier le profil" sur ProfileScreen
2. Entre en mode édition avec des champs modifiables
3. L'utilisateur modifie nom/email
4. Appelle editProfile() depuis AuthContext
5. AuthContext appelle localDatabase.editUser()
6. La base de données met à jour l'utilisateur dans le magasin en mémoire
7. L'utilisateur mis à jour est enregistré dans le contexte et AsyncStorage
8. L'écran de profil affiche les informations mises à jour

UTILISATION D'ASYNC STORAGE
================================================================================

Clés de stockage :
- 'loggedUser' - Stocke l'objet utilisateur authentifié actuel

Opérations :
- Enregistrer : AsyncStorage.setItem('loggedUser', JSON.stringify(user))
- Charger : AsyncStorage.getItem('loggedUser') → Parse JSON
- Supprimer : AsyncStorage.removeItem('loggedUser')

Points d'utilisation :
1. Lors d'une connexion réussie - enregistrer l'utilisateur
2. Lors d'une inscription réussie - enregistrer l'utilisateur
3. Au lancement de l'application - charger l'utilisateur enregistré
4. Lors de la déconnexion - supprimer l'utilisateur
5. Lors de la mise à jour du profil - mettre à jour l'utilisateur enregistré

Persistance des données :
- Persiste entre les sessions d'application
- Survit à la fermeture forcée de l'application
- Effacé lors de la désinstallation de l'application
- Stockage spécifique à la plateforme (iOS/Android/Web)
